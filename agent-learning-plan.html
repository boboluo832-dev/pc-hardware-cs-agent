AI 智能体开发学习路线

从零到生产力 · 系统化学习计划与知识点总结

第一阶段 · 2-4 周

基础认知与环境搭建

🧠 LLM 基本原理

理解大语言模型的工作方式，为后续开发打下认知基础。

  • Transformer 架构概览（Attention 机制）
  • Token 与 Tokenization 原理
  • 上下文窗口（Context Window）限制
  • Temperature / Top-P 采样策略
  • System Prompt vs User Prompt 的区别

知识点总结

LLM 本质是"下一个 token 预测器"。理解 token 计费、上下文长度限制、temperature 对输出随机性的影响是调用 API 的前提。不需要深入数学推导，但要知道模型的能力边界在哪里。

🔌 API 调用基础

掌握主流 LLM 提供商的 SDK 使用方法。

  • Anthropic Claude API（Messages API）
  • OpenAI Chat Completions API
  • 流式响应（Streaming）处理
  • 错误处理与重试策略
  • API Key 管理与安全实践

知识点总结

所有 agent 的底层都是 API 调用。重点掌握：消息格式（role/content）、流式输出处理、rate limit 应对。建议从 Anthropic SDK 入手，其 tool_use 设计最清晰。

✍️ Prompt Engineering

系统化的提示词设计方法论。

  • Few-shot / Zero-shot 提示
  • Chain-of-Thought（思维链）
  • 角色设定与约束注入
  • 输出格式控制（JSON Mode）
  • Prompt 版本管理与 A/B 测试

知识点总结

Prompt 是 agent 的"灵魂"。好的 prompt 要做到：明确角色、给出示例、约束输出格式、预设边界条件。CoT 能显著提升推理任务准确率。生产环境中 prompt 需要版本管理。

第二阶段 · 2-4 周

智能体核心机制

🔧 Tool Use / Function Calling

让 LLM 具备调用外部工具的能力，是 agent 的核心能力。

  • Tool 定义（JSON Schema 描述参数）
  • 工具调用流程：LLM 决策 → 执行 → 结果回传
  • 多工具并行调用
  • 工具结果的错误处理
  • 安全边界：哪些工具需要人工确认

知识点总结

Tool Use 是 agent 从"聊天机器人"进化为"执行者"的关键。核心循环：LLM 输出 tool_use → 你执行工具 → 把 tool_result 回传 → LLM 继续推理。设计工具时要让参数描述足够清晰，LLM 才能正确调用。

🔄 ReAct 模式

推理-行动-观察的循环，是最经典的 agent 架构。

  • Reasoning（推理当前状态）
  • Action（选择并执行动作）
  • Observation（观察执行结果）
  • 循环终止条件设计
  • 最大步数限制与超时处理

知识点总结

ReAct = Reason + Act。agent 在每一步先"想"（我现在该做什么），再"做"（调用工具），最后"看"（分析结果决定下一步）。关键是设计好终止条件，防止无限循环烧钱。

💾 Memory 机制

让 agent 具备记忆能力，支撑长期交互。

  • 短期记忆：对话上下文管理
  • 长期记忆：向量数据库存储
  • 工作记忆：当前任务状态追踪
  • 记忆检索：Embedding + 相似度搜索
  • 记忆淘汰与压缩策略

知识点总结

上下文窗口有限，memory 解决"agent 健忘"问题。短期靠滑动窗口/摘要压缩，长期靠向量数据库（如 Pinecone、Chroma）。关键挑战：检索相关性和记忆更新时机。

📋 状态管理与对话编排

管理复杂的多轮对话流程。

  • 对话状态机设计
  • 上下文压缩与摘要
  • 多轮任务的断点续传
  • 并发对话隔离
  • 会话持久化存储

知识点总结

生产级 agent 必须处理：用户中途离开后恢复、多用户并发、对话过长时的上下文压缩。状态机模式适合流程固定的场景，自由对话则需要更灵活的状态追踪。

第三阶段 · 3-4 周

框架实战与 RAG

🏗️ 主流框架掌握

选择一个框架深入，快速构建可用的 agent 应用。

  • LangChain / LangGraph：图编排、链式调用
  • CrewAI：多角色协作框架
  • Anthropic Agent SDK：轻量级官方方案
  • Vercel AI SDK：前端友好的流式方案
  • 框架选型原则：复杂度 vs 灵活度权衡

知识点总结

框架的价值在于抽象重复逻辑（工具注册、消息管理、错误重试）。初学建议：简单场景直接用 SDK 裸写，复杂编排再引入 LangGraph。不要为了用框架而用框架，理解底层原理比框架 API 更重要。

📚 RAG（检索增强生成）

让 agent 基于私有知识库回答问题。

  • 文档切分策略（Chunk Size / Overlap）
  • Embedding 模型选择与对比
  • 向量数据库：Chroma / Pinecone / Weaviate
  • 检索策略：相似度 / MMR / 混合检索
  • Reranking 与上下文窗口填充

知识点总结

RAG 是最常见的 agent 落地场景。核心流程：文档 → 切片 → Embedding → 存入向量库 → 用户提问时检索相关片段 → 拼入 prompt。难点在切分粒度和检索质量，chunk 太大噪音多，太小丢上下文。

🔗 MCP（Model Context Protocol）

标准化的工具接入协议，agent 生态的连接器。

  • MCP 协议架构：Client / Server / Transport
  • Resources、Tools、Prompts 三大原语
  • 编写自定义 MCP Server
  • 与现有 API 的桥接模式
  • 安全性：权限控制与沙箱

知识点总结

MCP 是 Anthropic 推出的开放协议，目标是让 agent 像 USB 一样即插即用地接入各种数据源和工具。掌握 MCP 意味着你的 agent 可以复用整个生态的 server，而不用每个集成都从零写。

第四阶段 · 4-6 周

多智能体与高级架构

👥 多智能体协作

多个 agent 分工合作，解决复杂任务。

  • 角色分工设计（Researcher / Writer / Reviewer）
  • 通信模式：共享黑板 vs 消息传递
  • 任务分解与分配策略
  • 冲突解决与共识机制
  • Supervisor 模式 vs Peer-to-Peer 模式

知识点总结

多 agent 的核心价值：专业化分工降低单个 agent 的 prompt 复杂度。Supervisor 模式（一个调度者 + 多个执行者）最稳定，适合生产环境。Peer 模式灵活但难调试。关键是设计好 agent 间的信息传递格式。

📐 Plan-and-Execute 架构

先规划再执行，适合复杂多步骤任务。

  • Planner Agent：任务分解与计划生成
  • Executor Agent：逐步执行计划
  • 动态重规划：执行失败时调整计划
  • 计划验证与可行性检查
  • 人机协作：关键节点人工审批

知识点总结

对于需要 5+ 步骤的复杂任务，先让 LLM 生成完整计划再逐步执行，比 ReAct 的逐步摸索更可靠。关键设计：计划要可序列化、支持部分重试、允许人工干预修改。

🛡️ 安全与可靠性

让 agent 在生产环境中安全稳定运行。

  • Prompt Injection 防御
  • 输出验证与 Guardrails
  • 权限最小化原则
  • Human-in-the-Loop 设计
  • 成本控制与 Token 预算

知识点总结

agent 能执行动作意味着风险放大。必须做到：敏感操作需人工确认、输出经过格式校验、工具权限按最小原则分配、设置 token 用量上限防止失控循环。Prompt injection 是最大安全威胁，需要多层防御。

第五阶段 · 4-8 周

生产化与评估体系

📊 评估与测试（Eval）

量化 agent 的表现，持续迭代优化。

  • 评估指标设计：准确率、完成率、延迟
  • 测试集构建：Golden Dataset
  • 自动化回归测试
  • A/B 测试框架
  • LLM-as-Judge 评估模式

知识点总结

没有 eval 的 agent 就是在盲飞。核心方法：构建标注好的测试用例集，每次改 prompt/工具后跑一遍对比。LLM-as-Judge（用另一个 LLM 评分）是低成本替代人工评估的方案，但要注意评估者偏差。

🚀 部署与运维

将 agent 从 demo 推向生产环境。

  • 容器化部署（Docker / K8s）
  • 异步任务队列（长时间运行的 agent）
  • 可观测性：日志、Trace、Metrics
  • LangSmith / Langfuse 追踪平台
  • 灰度发布与回滚策略

知识点总结

生产级 agent 需要完整的可观测性：每次 LLM 调用的 input/output 都要记录（用 LangSmith 或 Langfuse），方便排查"为什么 agent 做了奇怪的事"。异步队列处理长任务，避免 HTTP 超时。

💰 成本优化

在效果和成本之间找到最佳平衡点。

  • 模型分层：简单任务用小模型，复杂任务用大模型
  • Prompt Caching 利用
  • 批量处理（Batch API）
  • 缓存策略：相似问题复用结果
  • Token 用量监控与预警

知识点总结

agent 的成本 = 调用次数 × 每次 token 数 × 单价。优化手段：路由分流（Haiku 处理简单判断，Opus 处理复杂推理）、利用 prompt caching 减少重复计算、对高频相似请求做语义缓存。
